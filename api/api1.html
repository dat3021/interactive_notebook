1. Bản Chất API & Mô Hình Request - Response

Cách thức Client và Server trao đổi thông điệp qua môi trường mạng.

Trong kiến trúc phần mềm hiện đại, Client (Web, App di động) không truy cập trực tiếp vào Cơ sở dữ liệu. Thay vào đó, Client gửi một **HTTP Request** chứa thông tin yêu cầu tới API Endpoint của Server. Server xử lý nghiệp vụ và trả về **HTTP Response** (thường dưới dạng JSON) kèm theo **Status Code** phản ánh kết quả.

Mô hình Chu kỳ Giao tiếp Client - API Server

💻 📱

Client (Trình duyệt / Mobile App)

Khởi tạo HTTP Request (URL, Header, Body payload, Auth Token)

1. HTTP REQUEST ➔ GET /api/v1/products (Header: Bearer Token)
2. HTTP RESPONSE 🔒 Status 200 OK - Payload: JSON Array

API Server & Backend

Xác thực Auth, kiểm tra router, gọi Database & trả về kết quả JSON

2. So Sánh Các Kiểu Kiến Trúc API (API Architectures)

Phân tích đa chiều giúp chọn lựa giải pháp phù hợp cho bài toán hệ thống.

Không có một kiến trúc API duy nhất đáp ứng cho mọi bài toán. **REST** là chuẩn phổ biến cho ứng dụng Web thông thường nhờ sự đơn giản; **GraphQL** tối ưu bandwidth cho ứng dụng di động phức tạp; **gRPC** đáp ứng tốc độ cực cao cho Microservices nội bộ; và **WebSockets** phục vụ ứng dụng thời gian thực (Real-time).

So Sánh Đặc Tính Các Kiến Trúc API

Đánh giá trên thang điểm 1-10 về độ linh hoạt, hiệu năng, sự phổ biến và độ phức tạp.

REST API

Dựa trên HTTP Resource, cấu trúc đơn giản, cache tốt. Phù hợp cho 80% ứng dụng Web tiêu chuẩn.

GraphQL

Cho phép Client truy vấn chính xác trường dữ liệu cần thiết qua 1 Endpoint. Khắc phục Over-fetching.

gRPC / RPC

Sử dụng Protobuf & HTTP/2 cho tốc độ siêu nhanh. Sự lựa chọn hoàn hảo cho Microservices nội bộ.

WebSockets

Kết nối 2 chiều liên tục (Full-duplex). Dùng cho Chat app, Chứng khoán, Game Online, Live Tracking.

3. Chuẩn Giao Thức HTTP, Methods & Status Codes

Nắm vững các quy chuẩn phản hồi dữ liệu và động từ điều khiển.

Mỗi request API đều sử dụng các phương thức HTTP Method nhất định để thể hiện hành động (CRUD). Đồng thời, Server bắt buộc phải phản hồi bằng các Mã trạng thái (Status Code) chuẩn hóa để giúp Client biết request thành công hay gặp lỗi.

Phân Nhóm Mã Trạng Thái HTTP (Status Codes)

Các dải mã chuẩn hóa biểu thị trạng thái phản hồi từ Server.

Lưu ý quan trọng: Luôn trả về 4xx nếu lỗi do thông tin từ Client gửi sai và 5xx nếu Server bị sập/lỗi logic nội bộ.

Tần Suất Sử Dụng Phương Thức HTTP (CRUD)

Các động từ tương tác dữ liệu chuẩn RESTful.

Quy tắc Idempotency: GET, PUT, DELETE có tính lặp lại (Idempotent), trong khi POST sẽ tạo thêm tài nguyên mới mỗi lần gọi.

4. Bảo Mật API & Phân Quyền Truy Cập

Các cơ chế phòng thủ bảo vệ API khỏi nguy cơ rò rỉ dữ liệu và tấn công mạng.

API công khai trên Internet là mục tiêu hàng đầu của các cuộc tấn công DDoS và đánh cắp dữ liệu. Lập trình viên bắt buộc phải triển khai phân biệt giữa **Authentication** (Xác thực xem người dùng là ai) và **Authorization** (Phân quyền người dùng được phép làm gì).

🔑

API Key

Chuỗi định danh gửi qua Header/Query string. Dùng cho việc định danh Ứng dụng hoặc tích hợp Dịch vụ bên thứ ba đơn giản.

🛡️

JWT (JSON Web Token)

Token mã hóa chứa Stateless Payload. Rất phổ biến cho đằng sau đợt đăng nhập thành công của người dùng trên Web/App.

🌐

OAuth 2.0

Ủy quyền tiêu chuẩn cho phép người dùng đăng nhập bằng tài khoản Google, Facebook, GitHub mà không lộ mật khẩu.

⚡

Rate Limiting & CORS

Giới hạn số request/phút để tránh DDoS/Spam và cài đặt cấu hình CORS kiểm soát tên miền nào được phép truy cập API.

5. Kiến Trúc Luồng Xử Lý Backend (Backend Execution Pipeline)

Hành trình chi tiết của một Request từ khi cập bến Server đến Cơ sở dữ liệu.

Khi một HTTP Request được gửi tới Server, nó phải đi qua nhiều lớp kiến trúc được chia tách rõ ràng (Layered Architecture) nhằm đảm bảo nguyên tắc Clean Code và khả năng mở rộng.

Lớp 1

Router

Điều hướng URL /users/123 đến đúng Controller tương ứng.

Lớp 2

Middleware & Auth

Kiểm tra JWT Token, Rate Limit, Validate tham số đầu vào.

Lớp 3

Controller

Tiếp nhận Request, gọi các hàm Service và chuẩn hóa Response JSON.

Lớp 4

Service (Logic)

Thực hiện Business Logic chính (Tính toán, xử lý thanh toán, gửi Email).

Lớp 5

Database & Cache

Truy vấn CSDL (PostgreSQL, MongoDB) hoặc lưu đệm Cache (Redis).

Thiết kế giúp dễ viết Unit Test độc lập cho từng Layer. Chuẩn Pattern: MVC / Clean Architecture

6. Lộ Trình Học API Từng Bước Cho Người Mới

Các cột mốc thực hành giúp bạn thành thạo từ lý thuyết đến thực chiến.

1

Hiểu Lý Thuyết Mạng & HTTP Protocol

Nắm vững Client-Server, HTTP Methods (GET, POST, PUT, DELETE), Status Codes (200, 404, 500) và cấu trúc Request Header/Body.

2

Thực Hành Gọi API Với Postman / Hoppscotch

Sử dụng các Public API miễn phí (JSONPlaceholder, PokéAPI) để tập thử nghiệm gửi request, truyền Auth Token và xem dữ liệu JSON phản hồi.

3

Tự Viết RESTful API Với Một Ngôn Ngữ Backend

Chọn 1 Framework phổ biến (Node.js/Express, Python/FastAPI, Java/Spring Boot) để dựng ứng dụng CRUD cơ bản kết nối CSDL (PostgreSQL / MongoDB).

4

Tích Hợp Bảo Mật & Đóng Gói Swagger Docs

Cài đặt Đăng nhập bằng JWT Token, cấu hình Rate Limiting và tự động sinh Tài liệu API với OpenAPI / Swagger Spec cho Frontend tra cứu.
